# «Ведьмин домик» 0.3 — редактор персонажа

## Что уже работает

- Клик на аватар в правом боковом меню открывает отдельный редактор.
- Слева — оригинальная модель из отдельных SVG в одинаковой системе 600 × 1400.
- Базовые файлы: `legs.svg`, `body.svg`, `neck.svg`, `arm_left.svg`, `arm_right.svg`, `head.svg`, `top_basic.svg`, `shorts_basic.svg`.
- `all_basic.svg` не рендерится и не загружается автоматически.
- Справа — имя, 5 категорий, цвета кожи, кнопки сохранения и отмены.
- Сохраняется `character.appearance` внутри прежнего `localStorage` ключа `vedmin-domik-save-v1`. Старый прогресс не сбрасывается.
- Главные разделы игры, старый инвентарь, огород, котёл и торговля не переписаны.
- Поддерживается мобильный экран: модель сверху, настройки под ней.
- Гардеробная берётся из существующего `assets/backgrounds/witch_wardrobe.png`.

## Какие файлы нужно загрузить в GitHub

В корне репозитория `witch-house`:

1. ЗАМЕНИТЬ `index.html`
2. ЗАМЕНИТЬ `game.js`
3. ДОБАВИТЬ `character-editor.js`
4. ДОБАВИТЬ `character-editor.css`
5. ДОБАВИТЬ `assets/character/catalog.json`

**Не удалять и не перезаписывать** `assets/character/base/*.svg` и `assets/backgrounds/witch_wardrobe.png`. Они уже лежат в вашем GitHub; их нет в архиве обновления, потому что у нас нет оригинальных исходников. Не заменяйте их иллюстрациями из скриншотов.

Код собран на базе ранее подготовленной v0.2. Перед загрузкой заменяемого `game.js` сохраните копию, если в репозитории есть более свежие изменения.

После публикации откройте игру на GitHub Pages, обновите страницу через Ctrl+F5. Нажмите бургер → аватар.

## Структура базового персонажа

```text
assets/
  backgrounds/
    witch_wardrobe.png             ← уже есть на GitHub
  character/
    catalog.json                  ← новый файл
    base/
      head.svg                     ← уже есть на GitHub
      body.svg
      neck.svg
      legs.svg
      arm_left.svg
      arm_right.svg
      top_basic.svg
      shorts_basic.svg
      all_basic.svg                ← только сравнительный образец
```

Все слои должны иметь одинаковое экспортное поле 600 × 1400, одинаковый `viewBox` и прозрачный фон. Ничего дополнительно двигать относительно общей системы координат не нужно.

## Как добавлять новые элементы без изменения кода

Создайте папки `assets/character/eyes/`, `hair/`, `expressions/`, `clothing/` и сохраните туда свои SVG в том же кадре 600 × 1400. Затем отредактируйте только `assets/character/catalog.json`.

Пример (ПОКА ЭТИХ ФАЙЛОВ НЕТ; имена и позиции иллюстративные):

```json
{
  "version": 1,
  "eyes": [
    {"id":"eyes_01","name":"Карие глаза","file":"assets/character/eyes/eyes_01.svg"}
  ],
  "hair": [
    {"id":"hair_01","name":"Волнистые волосы","back":"assets/character/hair/hair_01_back.svg","front":"assets/character/hair/hair_01_front.svg"}
  ],
  "expressions": [
    {"id":"smile_01","name":"Улыбка","file":"assets/character/expressions/smile_01.svg"}
  ],
  "clothing": [
    {"id":"dress_01","name":"Платье","back":"assets/character/clothing/dress_01_back.svg","front":"assets/character/clothing/dress_01_front.svg","top":"assets/character/clothing/dress_01_top.svg","bottom":"assets/character/clothing/dress_01_bottom.svg"}
  ]
}
```

`hair.back` рисуется позади персонажа; `hair.front` — поверх лица и одежды. У одежды `back` позади, `front` спереди. `top` заменяет базовый белый топ, `bottom` заменяет шорты. Если необязательные слои не указаны, они не появятся.

Можно отдельно указать `thumbnail` — путь к SVG-миниатюре для кнопки. Без него у кнопки пока символ «✧».

До загрузки реальных SVG соответствующие разделы **пустые**, никаких выдуманных волос, глаз или нарядов нет.

## Оттенки кожи

Цвет кожи изменяется только на анатомических слоях. SVG-контуры, размеры и позиции не меняются. Алгоритм перекрашивает распознанные тёплые оттенки заливки; нейтральные линии и белое бельё остаются нетронутыми. Результат зависит от точных цветов в оригинальных Figma-файлах. Поэтому после первой загрузки **нужно проверить каждый тон кожи** на реальных SVG: если художнические цвета нестандартные, корректируем правила перекраски под них, а не перерисовываем персонажа.

## Отдельная проверка

Откройте `all_basic.svg` как отдельную картинку и сравните исходный образец с собранной моделью на странице. Если контуры не совпадают, проверьте прозрачные поля, `viewBox` и экспорт каждого SVG.

## Проверка сохранений

Ключ данных остался прежним: `vedmin-domik-save-v1`. Новое поле `character.appearance` не мешает существующему сохранению. Кнопка «Отмена» не записывает изменённые цвета, «Сохранить образ» записывает и возвращает домой. `Дневник` — отдельный раздел, где в имеющейся версии предусмотрены функции импорта/экспорта сохранения.

## Важное ограничение

Оригинальные SVG и фон присутствуют только в пользовательском GitHub. В среде подготовки обновления GitHub не удалось прочитать, поэтому живое совмещение 600 × 1400 с настоящими файлами **ещё не проверено визуально**. Код не заменяет отсутствующую графику и выводит предупреждение при ошибке её загрузки.
